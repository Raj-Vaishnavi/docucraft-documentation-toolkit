# DocuCraft writing style guide

## Overview

Use this guide to create documentation that readers can scan, understand, and act on.

## Before you begin

Know the reader, the task they need to complete, and the product facts approved by the subject-matter expert.

## Procedure

1. Start with the reader’s goal and state what the feature does.
2. Put prerequisites before numbered steps.
3. Write one action per step; begin with a direct verb.
4. Use the exact UI label in **bold** and match its capitalization.
5. Prefer short sentences, concrete nouns, and active voice.
6. Explain expected results and recovery paths when they help the reader.
7. Use `SafeRestore` and `recovery point` consistently.
8. Add descriptive link text and check every relative link.

## Troubleshooting

Avoid unsupported claims, invented UI labels, vague references such as “this,” and promises about performance or availability. If a fact is uncertain, mark it for review instead of guessing. See the [human fact-check checklist](../prompts/human-fact-check-checklist.md).
